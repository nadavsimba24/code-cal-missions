# Strix — הנחיות בדיקה ל-CODE-CAL MISSIONS

מערכת ניהול עבודה עירונית (FastAPI + SQLAlchemy). המידע כולל פניות תושבים
ובקשות היתר עם פרטים מזהים (ת״ז, טלפון, כתובת). מקד את הבדיקה בנקודות הבאות,
שזוהו כחשודות בסקירה ידנית:

## 1. אימות וזהות
- אין אימות אמיתי: הזהות מגיעה כפרמטר `user_id` / `actor_id` מהלקוח.
- בדוק אם שינוי המספר בבקשה מאפשר לפעול בשם משתמש אחר, כולל מנהל מערכת.

## 2. הרשאות (IDOR / broken access control)
- כל endpoint שמשנה נתונים: נסה לגשת ללוח/פריט/סביבה של משתמש אחר.
- בדוק את מסלולי ה-AI: `POST /api/ai/query` ו-`POST /api/swarm/think`.
  הכלים שהמודל מפעיל (create_task/update_task/delete_task/list_users)
  חשודים כעוקפים את מודל ההרשאות — נסה למחוק/לשנות פריט בלוח שאין לך גישה אליו.

## 3. פרוקסי LLM פתוח
- `POST /api/llm/v1/chat/completions` חשוד כפתוח ללא אימות — בדוק אם אפשר
  לצרוך אותו כצד שלישי (ניצול מכסת API).

## 4. הזרקות ו-XSS
- העלאת קבצים: `POST /api/upload` — נסה להעלות HTML/SVG ולבדוק אם הם
  מוגשים חזרה `inline` מאותו origin (stored XSS).
- שדות תוכן חופשי (תיאור משימה, פנייה) — הזרקת סקריפט, וגם prompt injection
  שמגיע להקשר של מודל ה-AI.

## 5. CORS
- `allow_origins=["*"]` — בדוק אם אתר זר יכול לקרוא ל-API מדפדפן המשתמש.

## גבולות
- אל תבצע מחיקה המונית או פעולות הרסניות בלתי הפיכות מעבר להוכחת היתכנות.
- לכל ממצא ספק שלב-שחזור מדויק כדי שנוכל לאמת ולתקן.
