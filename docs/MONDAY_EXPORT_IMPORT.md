# ייצוא לוח ממאנדיי וייבוא ל-CODE-CAL MISSIONS

**תאריך:** 08.10.2026 · **גרסה:** 1.0 · **קהל יעד:** מי שמריץ את ההגירה בפועל
**מטרה:** איך מוציאים לוח ממאנדיי, איך מחברים את התשובות לקובץ אחד, ומה לבדוק לפני ואחרי ההעלאה.

> כל מספר במסמך הזה מגיע מהגירה אמיתית: הלוח **ניהול פרויקטים 2025** (`6257071922`) — 320 פריטים,
> 71 תתי־פריטים, 605 שיחות, 8,959 רשומות היסטוריה.

---

## 1. למה שלוש בקשות ולא אחת

הייבוא קורא את תשובת ה-API של מאנדיי, לא ייצוא אקסל: ב-xlsx אין סוגי עמודות, ובלעדיהם הייבוא מנחש
בכל עמודה. השאילתות עצמן נמצאות ב-[backend/monday_export.graphql](../backend/monday_export.graphql),
ומי שמריץ אותן דרך פוסטמן מייבא את
[backend/monday_export.postman_collection.json](../backend/monday_export.postman_collection.json).

| # | הבקשה | מה היא מביאה | מתי מריצים |
|---|---|---|---|
| 1 | **הלוח** | שם, קבוצות, הגדרות עמודות, 500 פריטים, תתי־פריטים, שיחות, קבצים | תמיד |
| 2 | **ההיסטוריה** | `activity_logs` — מי שינה מה ומתי, ורשימת המשתמשים | תמיד |
| 3 | **עמוד הבא** | המשך הפריטים לפי `cursor` | רק אם הלוח ארוך מ-500 שורות |

ההיסטוריה היא בקשה נפרדת כי יחד עם 500 פריטים היא לא נכנסת בתקרת המורכבות של מאנדיי: לוח של 320
פריטים חזר `REQUEST_MAX_COMPLEXITY_EXCEEDED` בעלות 5,125,801 מול תקרה של 5,000,000.

> ⚠ **בקשה אחת = operation אחד.** הקובץ `monday_export.graphql` מחזיק שלושה. בקשה שנושאת שניים חוזרת
> HTTP 200 עם `operation name is required when multiple operations are defined` — שגיאה שנראית כמו
> טוקן מת. תיבת ה-query בפוסטמן *מוסיפה* להדבקה במקום להחליף, והיא נגללת, אז קל לא לראות query שני
> מתחת לשורות הנראות. לכן מריצים מהקולקשן, שבו כל בקשה מחזיקה operation אחד.

## 2. המלכודת היחידה שמאנדיי לא מדווח עליה

`boards(ids: $boardId)` עם משתנה ריק הוא `boards(ids: [])`, ומאנדיי עונה לזה **בדיוק כמו ל-`ids: null`**:
25 הלוחות הראשונים בחשבון, HTTP 200, בלי שום שגיאה.

ככה זה נראה כשזה קורה — תשובת היסטוריה אמיתית שחזרה כך:

```
boards: 25
  18374015793  logs: 10000
  18382373316  logs:  4251
  ...                                ← 20,064 רשומות של 25 לוחות
  6581100288   logs:     7           ← והלוח שביקשנו, 6257071922, בכלל לא ביניהם
```

הלוח המבוקש היה ישן יותר מכל 25 הלוחות שחזרו, ולכן נפל מתחת לעמוד הראשון. הקובץ נראה מלא
(15MB של לוגים) ולא הכיל ולו שורה אחת מהלוח שהוגר.

**למה זה קורה גם כשהמשתנה "מלא":** בגוף ה-GraphQL כתוב `{"boardId": [{{boardId}}]}`. אם למשתנה יש
רק *Initial value* בלי *Current value*, או שהוא מוגדר באוסף אחר מזה שממנו שלחת — נשלח `[]`.

**איך נמנעים:** הקולקשן שבריפו עוצר את הבקשה לפני השליחה אם `boardId` ריק, ובודק בתשובה שחזר בדיוק
לוח אחד, ושזה הלוח שביקשת. מי שמריץ מחוץ לקולקשן — הכי בטוח לוותר על המשתנה ולכתוב את המזהה בשאילתה:

```graphql
boards(ids: [6257071922]) { ... }
```

**איך בודקים בדיעבד:** בתשובה צריך להיות לוח אחד.

```bash
python -c "
import json,sys
d=json.load(open(sys.argv[1]))
for i,r in enumerate(d if isinstance(d,list) else [d]):
    b=(r.get('data') or {}).get('boards') or []
    print(i, 'boards:', len(b), [x.get('id') for x in b][:3])
" board.json
```

`boards: 1` — תקין. `boards: 25` — הבקשה לא סיננה, הריצי אותה שוב.

## 3. התהליך, שלב אחר שלב

### שלב 1 — הלוח

1. בפוסטמן: ייבוא הקולקשן, ואז **Variables** של האוסף — `MONDAY_TOKEN` ו-`boardId` (מזהה הלוח מה-URL
   שלו). למלא את עמודת **Current value**, לא רק Initial.
2. להריץ את בקשה 1, לשמור את התשובה כ-`board.json`.
3. לבדוק את `cursor` בתשובה: אם הוא **אינו** `null`, הלוח ארוך מ-500 שורות — להריץ את בקשה 3 עם
   אותו cursor, שוב ושוב, עד ש-`cursor` חוזר `null`. כל תשובה נשמרת כקובץ.

### שלב 2 — ההיסטוריה

להריץ את בקשה 2 ולשמור כ-`log.json`. היא מביאה גם את `users` — בלי זה כל שורה בלוג תירשם "מערכת",
כי הלוג של מאנדיי נותן מזהה משתמש ולא שם.

אם חזרו בדיוק **10,000** רשומות — זו התקרה של השאילתה, וייתכן שיש עוד. להריץ שוב עם `page: 2`:
אם חוזר `[]`, יש את הכל; אם לא, גם התשובה הזו נכנסת לקובץ.

### שלב 3 — המיזוג

כל התשובות נכנסות לקובץ אחד, כמערך JSON. הסדר לא משנה — הייבוא קורא אותן כלוח אחד:

```json
[ {תשובת הלוח}, {תשובת ההיסטוריה}, {עמוד 2}, {עמוד 3} ]
```

```bash
python -c "
import json
out=[json.load(open(f)) for f in ['board.json','log.json']]
json.dump(out, open('merged.json','w'), ensure_ascii=False)
print('merged.json:', len(out), 'responses')
"
```

> המיזוג הוא העטיפה בלבד — `[` , פסיק, `]`. הוא לא מתקן תשובה שחזרה שגויה, ואם ערבבת תשובה ישנה
> עם חדשה הקובץ ייראה תקין לגמרי. כדאי להריץ את בדיקת `boards: 1` מסעיף 2 על הקובץ הממוזג.

### שלב 4 — ההעלאה

במערכת, ב-**+** שבסרגל הצד → **לוח** → **יצירת לוח מקובץ**, ולבחור את `merged.json`. (אותו דבר יושב
גם בתפריט של לוח קיים, תחת *ייבוא לוח מקובץ*.) אפשר לתת שם; בלי שם הלוח מגיע בשם שלו ממאנדיי.
שתי הדרכים הן מהמחשב בלבד — בנייד הייבוא לא מוצע, וצריך הרשאת יצירת לוח.

## 4. מה לבדוק בדוח הייבוא

הדוח נפתח מיד אחרי הייבוא, ואפשר לשמור אותו כ-PDF. אלה השורות שמשנות:

| בדוח | המשמעות | מה עושים |
|---|---|---|
| **הקובץ אינו הלוח המלא** | ב-`cursor` נשאר ערך — הייצוא נעצר באמצע הלוח | לאסוף את שאר העמודים (בקשה 3) ולייבא מחדש |
| **בקובץ היו עוד N לוחות** | בקשה רצה בלי `boardId` — ההיסטוריה של האחרים לא נכנסה | להריץ את בקשת ההיסטוריה שוב עם המזהה |
| **היסטוריית הלוח לא יובאה** | או שהשאילתה לא ביקשה `activity_logs`, או שההיסטוריה שבקובץ שייכת ללוחות אחרים — הדוח מבחין בין השניים | לפי מה שהדוח אומר |
| **N רשומות רשומות על מערכת** | אנשים שהלוג מזהה במספר, ורשימת המשתמשים לא כוללת אותם | ראו סעיף 5 |
| **עמודות שלא יובאו / יובאו בסוג אחר** | כל עמודה עם הסיבה שלה | החלטה עסקית, לא תקלה |
| **עמודות נוסחה** | הערך המחושב יובא כטקסט, והנוסחה נשמרה בעמודה | אפשר להפוך לנוסחה חיה מתפריט העמודה, עמודה־עמודה |

## 5. מגבלות ידועות — אלה לא תקלות של הייבוא

**היסטוריה היא חלון, לא כל חיי הלוח.** מאנדיי שומר `activity_logs` לתקופה שתלויה בתוכנית. הדוח אומר
באיזה תאריך הלוג מתחיל, וזו עובדה על מאנדיי ולא על ההגירה.

**לרשומות המיובאות אין ביטול.** השינוי קרה במאנדיי, אולי לפני שנה; ביטול היה כותב ערך מהעבר על
הפריט כפי שהוא היום.

**רשימת המשתמשים היא החשבון כפי שהוא היום, והלוג הוא הלוח כפי שהיה.** בהגירה האמיתית הלוג נכתב
ב-21 ידיים ו-15 מהן לא היו ברשימה — 4,672 שורות בדרך ל"מערכת". הייבוא קורא שמות גם מעמודות האנשים
של הלוח, וזה החזיר 10 אנשים בשם. מה שנשאר:

- מזהה **שלילי** (`-4`) הוא מאנדיי עצמו — האוטומציות שלו. "מערכת" זו האמת לגביו.
- מזהה חיובי בלי שם הוא **אדם** שהקובץ לא יודע לנקוב בשמו — מי שכבר אינו בחשבון ולא יושב באף תא
  אנשים בלוח. הדוח סופר אותם בנפרד ואומר כמה.

**קבצים מחזיקים שעה.** הקישורים שמאנדיי מחזיר ב-`assets { public_url }` חתומים לשעה אחת, והזמן
כתוב בתוך הקישור עצמו. ייצוא שיושב יום על הדיסק יגיע עם שמות הקבצים ובלי הבייטים — אז מייצאים
ומייבאים ברצף, באותה שעה. הדוח אומר כמה קבצים הגיעו כקישור וכמה פג תוקפם.

**חמש עמודות נוסחה לבקשה.** לוח עם יותר מחמש מקבל שגיאה או מחרוזות ריקות — מייצאים פעמיים, כל ריצה
עם `ids` אחרים של עמודות.

**אירועים שאין להם מקבילה.** חלק מסוגי האירועים של מאנדיי (שינוי הגדרות עמודה, מנוי/ביטול מנוי,
מעבר בין לוחות) לא נכנסים ללוג כאן. הדוח מונה אותם לפי סוג במקום להשמיט בשקט.

## 6. תסמין ← סיבה

| מה רואים | מה קרה |
|---|---|
| `הקובץ אינו תשובת API של מאנדיי: the file holds more than one board` | שתי תשובות שונות שהביאו פריטים — שני לוחות בקובץ אחד. ייבוא אחד בונה לוח אחד |
| הלוח עלה בלי היסטוריה, והדוח מדבר על לוחות אחרים | בקשת ההיסטוריה רצה בלי `boardId` (סעיף 2) |
| הלוח עלה, והדוח אומר שהשאילתה לא ביקשה היסטוריה | השאילתה שרצה היא גרסה ישנה, בלי `activity_logs` |
| כל שורות הלוג רשומות על "מערכת" | השאילתה לא ביקשה `users { id name email }` |
| עמודות נוסחה/מראה/חיבור ריקות בכל הפריטים | השאילתה לא ביקשה `display_value` — שלושת הסוגים האלה לא עונים ב-`text` בכלל |
| הכל עלה, אבל יש פחות פריטים ממה שבמאנדיי | `cursor` לא היה `null` ונשארו עמודים. הדוח אומר את זה במפורש |
| הכל עלה, אבל השינוי שעשיתי בקוד לא נראה | השרת רץ מלפני השינוי — להפעיל מחדש, ו-Cmd+Shift+R בטאב |
