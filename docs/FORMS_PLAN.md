## 3. מבנה הנתונים המוצע

נשאר באותו מקום — `board.settings.form` — ומתרחב.

```json
{
  "status": "draft",
  "access": "BOARD_MEMBERS",
  "token":  "a3f91b2c...",

  "questions": [
    {
      "field":    "col_8d21ba07",
      "label":    "כתובת מדויקת",
      "help":     "רחוב ומספר בית",
      "required": true,
      "hidden":   false,
      "order":    3,
      "settings": { "min": "", "max": "" }
    }
  ],
  "design": {
    "title": "...", "intro": "...", "submit_label": "שלח",
    "thanks": "...", "accent": "#0073ea", "logo_token": null
  },
  "target": { "group_id": 12 },

  "live": { "questions": [...], "design": {...}, "target": {...} },
  "published_at": "2026-...",
  "published_by": 4
}
```

### שלוש הכרעות בתוך המבנה

**`label` נשמר ולא נקרא מהעמודה.** זה בדיוק הפער מסעיף 2. הקישור (`field`) שייך ללוח; הניסוח
(`label`, `help`, `required`) שייך לטופס. `type` נשאר נגזר מהעמודה — הוא לא ניסוח, הוא חוזה הנתונים,
ושאלה שתחזיק סוג משלה תוכל לכתוב ערך שהתא לא יודע לקרוא.

**`live` נפרד מהטיוטה.** עריכה כותבת ל־`questions`/`design`; הממלא רואה את `live` עד ללחיצה על
"פרסם". תקדים בקוד: `Automation.draft_version` ו־`AutomationVersion.is_draft` (`models.py:717`) —
"עריכה לכלל פעיל נכתבת כגרסת טיוטה... מה שמאפשר לערוך כלל פעיל בלי שהלוח ישתנה תחתיו באמצע היום".

**`access` ו־`token` הם שומרי סף של endpoint לא מאומת.** הם חייבים ולידציה קשיחה בשרת בכל כתיבה,
ולא להיסמך על כך שה־UI שולח ערך תקין.

### שאלה כפולה על אותו שדה

היום בלתי אפשרי: `currentForm()` ממפתח לפי `key` ומשתמש ב־`Set`. המבנה המוצע שומר על כך —
מערך `questions` עם `field` ייחודי, ללא `qid` נפרד. **מומלץ להשאיר כך ב־MVP**: "הגשה אחת ← רשומה אחת"
מחייב תשובה אחת לכל שדה, וכל פתרון לשתי תשובות לתא אחד הוא כלל שקוף שאיש לא ביקש.

## 4. פעולות API

### ניהול — קיים, מורחב

`PATCH /api/boards/{id}` עם מפתח `form` (`main.py:5774`) נשאר נקודת השמירה. מה שנוסף לו:

- ולידציה אמיתית של המבנה. היום הערך נכתב ל־`settings` **כמו שהוא**, בלי בדיקה — `s["form"] = data["form"]`.
  מבנה שגוי נשמר בשקט ומתפוצץ בצד הלקוח.
- כתיבה ל־`questions`/`design` בלבד. `live` לא ניתן לעריכה ישירה.
- `access`/`status` מוגבלים לערכים המוכרים.

endpoints חדשים:

| פעולה | הרשאה | מה עושה |
|---|---|---|
| `POST /api/boards/{id}/form/publish` | `admin` | מעתיק טיוטה → `live`, `status="published"` |
| `POST /api/boards/{id}/form/close` | `admin` | `status="closed"`; הכתובת מחזירה 410 |

### מילוי — מסלול חדש

| פעולה | זהות | מחזיר |
|---|---|---|
| `GET /api/public/forms/{token}` | לפי `access` | רק `live`. אף פעם לא `board_id`, לא שמות עמודות, לא חברי לוח |
| `POST /api/public/forms/{token}/submit` | לפי `access` | `{"ok": true}` + טקסט מ־`design.thanks`. **לא** מזהה הפריט |
| `POST /api/public/forms/{token}/upload` | לפי `access` | תאום לשימוש בהגשה אחת |

### שינוי ב־middleware

`PUBLIC_API_PATHS` (`main.py:98`) הוא `set` בהתאמה מדויקת ולא יתאים לנתיב עם תאום:

```python
PUBLIC_API_PREFIXES = ("/api/public/forms/",)
```

נבדק **אחרי** ההתאמה המדויקת. בתוך ה־handler נאכף `access` בעצמו: טופס `AUTHENTICATED` או
`BOARD_MEMBERS` קורא ל־`resolve_user` ידנית ומסרב בלעדיו. התחילית פותחת את הנתיב, לא את הטופס.

### מה ההגשה עושה

1. אחזור לפי `token` → חייב `status == "published"`, אחרת 410
2. אכיפת `access` + הגבלת קצב
3. ולידציה מול `live.questions` **בלבד** — תשובה לשאלה שאינה שם נזרקת בשקט
4. כל הכשלים נאספים ומוחזרים כ־400 אחד. אין יצירה חלקית ואין יצירה ואז עדכון
5. המרה ל־`title`/`assignee_ids`/`custom_fields` — אותה המרה שב־`Forms.submit` (`index.html:16573`)
6. קריאה אחת לליבת היצירה, `actor=None`, `source="form"`

**הסיכון הטכני המרכזי:** `create_task` (`main.py:7620`) כורך את `actor_id` בשמונה מקומות —
`_require_board_edit`, `created_by`, `_can_be_assigned`, `_filter_people_values`, `_merge_link_ids`,
`_audit`, התראות, `_run_automations`. חילוץ ליבה שתומכת ב־`actor=None` חייב להשאיר את כולם עובדים
בלי לפתוח מחדש את ה־IDOR שנסגר ב־`main.py:7647`.

## 5. מה נרשם על ההגשה

בלי טבלת הגשות. "הגשה תקינה יוצרת רשומה אחת" — הרשומה **היא** ההגשה, וטבלה נפרדת תיצור מקור אמת
שני שיסטה מהלוח ברגע שמישהו יערוך את הרשומה.

- שורת `AuditLog` בפעולה `create` עם `origin = {"form": true, "name": "...", "email": "..."}`.
  מנגנון קיים — `AuditLog.origin` (`models.py:1142`) נבנה בדיוק לגורם בלי חשבון, בייבוא ממאנדיי
- `task.custom_fields["_from_form"] = true` — כדי שאפשר יהיה לסנן "מה הגיע מהטופס"

## 8. פערים שלא נשאלו

### ליקוי אבטחה פעיל — לטפל ראשון

`POST /api/forms/submit` (`main.py:19025`) יוצר `Task` **בלי `_require_board_edit` ובלי `created_by`**,
עם `board_id` ברירת־מחדל 3. כל משתמש מאומת יכול להזריק רשומה לכל לוח במערכת, כולל כזה שלא הוזמן אליו.
זה בדיוק ה־IDOR ש־`create_task` סגר אצלו ב־`main.py:7647`. הפרונטאנד לא קורא ל־endpoint הזה כלל.

### הגנה מפני שימוש לרעה — נדרשת הכרעה

**אין במערכת הגבלת קצב כלשהי.** `POST .../submit` יהיה הכתיבה הלא־מאומתת הראשונה למסד הנתונים.
בלי הגנה, טופס `PUBLIC` אחד הוא דרך למלא לוח באלפי רשומות. המינימום: תקרה ל־`(token, IP)` בחלון זמן,
תקרה יומית, ו־`429` מסודר. `_client_ip` קיים (`main.py:9020`), אבל שמירת כתובות היא החלטת ארגון
(`_audit_ip_allowed`) — להגבלת קצב מספיק hash בזיכרון.

### קבצים יתומים

קובץ שהועלה ולא הוגש נשאר ב־`uploaded_files` לנצח. דרוש פינוי של מה שלא נקשר להגשה תוך 24 שעות.

### לאן הרשומה נוחתת

`create_task` עם `group_id = None` יוצר פריט בלי קבוצה. `target.group_id` חייב להיות חובה בפרסום,
עם ברירת מחדל לקבוצה הראשונה. קבוצה שנמחקה אחרי הפרסום מתנהגת כמו שדה שנמחק — הפרסום הבא נחסם.

### התאום

`token` הוא יכולת: מי שמחזיק בו ממלא. לכן `uuid4().hex` (כמו `UploadedFile.token`), ולא `board_id`.
החלטה נדרשת: "סגירת טופס" משהה את התאום או מבטלת אותו? **המלצה: משהה** — `closed` הוא מצב, והחייאה
חוזרת לאותה כתובת. החלפת תאום היא פעולה מפורשת ונפרדת.

### התראה על הגשה

`_notify` קיים. **המלצה: לא לבנות** — אוטומציית "כאשר נוצר פריט → הודע" כבר עושה בדיוק את זה,
והיא ניתנת להגדרה לכל לוח בנפרד.

### תיעוד מיושן

`CLAUDE.md` ו־`ROADMAP.md` עדיין מתארים את CityOS — GIS, BIM, SIRI, "9 משימות". המערכת בפועל היא
CODE-CAL MISSIONS עם אוטומציות, תצוגות שמורות, הרשאות עמודה וייבוא ממאנדיי. `CONVENTIONS.md` הוא
המסמך היחיד שעדיין מדויק.

## 9. מחוץ ל־MVP

רשום כדי שלא ייכנס בדרך:

- לוגיקה מותנית — שאלה שמופיעה לפי תשובה קודמת
- ריבוי עמודים בטופס
- שמירת טיוטה אצל הממלא
- עריכת הגשה אחרי שליחה

## נקודה פתוחה אחת

האפיון כותב "הגדרות השאלה והעיצוב עצמאיות מהלוח **ומטפסים אחרים**". עם טופס אחד ללוח —
המבנה הנוכחי — "טפסים אחרים" הם הטפסים של לוחות אחרים, וזה מתקיים מאליו.
אם הכוונה הייתה לכמה טפסים **על אותו לוח**, `board.settings.form` הופך ל־`board.settings.forms[]`
וכל השאר בתוכנית נשאר תקף. כדאי לאשר לפני משימה 1.
